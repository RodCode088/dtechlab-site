## 2.2 Typography System

### Typeface Stack

**Display / Hero:**  
`Geist` or `Inter Display` — weight 200–300  
Ultra-thin tracking: letter-spacing -0.04em to -0.06em  
Used for: hero headlines, section titles

**Body / Interface:**  
`Inter` or `Geist` — weight 300–400  
Used for: paragraphs, UI labels, navigation

**Monospace / Technical:**  
`Geist Mono` or `JetBrains Mono` — weight 400  
Used for: code snippets, data values, system labels, metrics

**Accent / Display 2:**  
`Neue Montreal` or `DM Sans` — weight 200 italic  
Used for: quotes, accent statements, editorial moments

### Type Scale
```
Display XL:  clamp(64px, 8vw, 120px) — Hero headlines
Display L:   clamp(48px, 6vw, 80px)  — Section titles
Display M:   clamp(36px, 4vw, 56px)  — Sub-section titles
Heading:     24–32px                 — Card titles, CTAs
Body L:      18–20px                 — Primary body copy
Body M:      15–16px                 — Secondary body, UI
Body S:      12–13px                 — Labels, captions, metadata
Mono:        13–14px                 — Technical data, code
```

### Typography Principles
- Headlines are always thin-weight — never bold for primary display
- Tight letter-spacing on large type creates precision feel
- Generous line-height on body copy (1.7–1.8) for readability
- Monospace for any number, metric, or system data point
- Mix of uppercase labels (tracking: +0.1em) and natural-case headlines

## 2.4 Visual Elements & Motifs

### Signature Visual Language

**1. The Grid Substrate**  
A subtle, barely-visible dot grid or line grid covers backgrounds — not as decoration but as a reference to engineering precision. Opacity: 2–4%.

**2. Frosted Panels (Glassmorphism — surgical use)**  
Cards and overlays use `backdrop-filter: blur(20px)` with near-invisible fill. Never stacked more than 1 level deep. Always dark-tinted, never bright.

**3. Signal Lines**  
Thin horizontal or diagonal lines of 1px that appear as structural elements — separating content, connecting visual anchors, or acting as animated "loading" indicators.

**4. Data Artifacts**  
UI screenshots, dashboard previews, system diagrams, and code fragments used as visual content — the product IS the visual.

**5. Luminous Edges**  
Border-top or border-left on cards uses a very subtle gradient from Signal/Plasma to transparent — creating the feel of internal illumination. `border-image: linear-gradient(to bottom, #5B6AFF22, transparent)`

**6. Depth Layering**  
Three distinct depth layers:  
- Layer 0: Background (Void/Abyss)  
- Layer 1: Content surfaces (cards, panels)  
- Layer 2: Floating elements (tooltips, modals, navigation)

# PART V — MOTION PHILOSOPHY

## 5.1 Motion Principles

**1. Physics, not animation**  
Every motion should feel like it obeys physical laws. Spring-based easing. Natural deceleration. Nothing bounces unless it has mass.

**2. Purposeful, not decorative**  
Animation communicates state, hierarchy, and flow — never for entertainment. If removing an animation breaks comprehension, it belongs. Otherwise, question it.

**3. Restraint as sophistication**  
The most premium products animate the least. Small, precise micro-interactions signal quality more than grand page transitions.

**4. Temporal precision**  
Standard durations:
```
Micro:    80–100ms  (button states, icon changes)
Short:    150–200ms (card hovers, tooltip entry)
Medium:   250–350ms (panel transitions, drawer open)
Long:     400–600ms (page transitions, hero entry)
Cinematic: 800ms+   (intro sequences, hero reveals)
```

## 5.2 Signature Motion Patterns

**Page Entry (Hero):**  
Content enters from opacity 0 + translateY(20px) â†’ natural position.  
Staggered: headline first, sub-copy 80ms later, CTA 80ms after that.  
Duration: 500ms. Easing: cubic-bezier(0.16, 1, 0.3, 1) — fast out, natural settle.

**Scroll-triggered sections:**  
Not every section needs an entrance. Reserve entrance animations for key content blocks.  
Use IntersectionObserver. Threshold: 0.15. No replay on scroll-back.

**Card hover:**  
Transform: translateY(-2px) + box-shadow intensify.  
Duration: 200ms. Easing: ease-out. Feels magnetic.

**CTA button:**  
Arrow suffix translates +4px on hover. Duration: 150ms. Easing: ease-out.  
Background shift is instant (0ms) then refines. Creates a snap feel.

**Data/dashboard animations:**  
- Number counters: Roll up from 0 to target value over 800ms when entering viewport
- Chart lines: Draw from left to right over 600ms, stroke-dashoffset technique
- Live indicators: Subtle pulse (scale 1.0 â†’ 1.15 â†’ 1.0, 2s loop, opacity 0.6)

**Page transitions (if SPA):**  
Outgoing page: opacity 1 â†’ 0, 150ms.  
Incoming page: opacity 0 â†’ 1, translateY(8px) â†’ 0, 250ms.  
Total transition: ~400ms. Feels like changing OS screens.

**The "System Boot" intro:**  
Homepage entry sequence:  
```
0ms:    Page black
200ms:  Dot grid fades in at 1% opacity
400ms:  Logo mark draws itself (SVG path animation, 400ms)
800ms:  Tagline appears (letter by letter, 30ms intervals)
1200ms: Hero content enters
```

Can be skipped after first visit (stored in localStorage).

# PART X — PRESENTATION & PROPOSAL SYSTEM

## 10.1 DTechLab Proposal Architecture

### Proposal philosophy:
A DTechLab proposal is not a quotation document. It is a systems brief — demonstrating deep understanding of the client's operational reality before presenting a solution.

### Structure:
```
PAGE 01: Cover
  — Client name + project codename
  — DTechLab logo
  — Date

PAGE 02: The Current State
  — Precise description of client's existing systems/gaps
  — Written as a diagnosis, not a sales pitch
  — Shows we listened

PAGE 03: The Problem, Stated Architecturally
  — Root cause analysis
  — Where the infrastructure fails
  — What this costs (time, money, opportunity)

PAGE 04: The Proposed System
  — High-level architecture diagram of the proposed solution
  — Visual system map: components, integrations, data flows
  — Not a feature list — a system overview

PAGE 05: The Build Plan
  — Phase 1 / Phase 2 / Phase 3
  — What gets built when, and why in that order
  — Dependencies made visible

PAGE 06: The Stack
  — Technologies, platforms, integrations used
  — Why each was chosen
  — Monospaced technical reference

PAGE 07: The Team
  — Who works on this project
  — Not bio pages — roles and responsibilities

PAGE 08: Investment
  — Clean pricing table
  — Per-phase breakdown
  — What's included / what's not

PAGE 09: Next Steps
  — Exactly what happens after signing
  — Timeline to kickoff
  — What we need from them
```

### Visual design of proposals:
- Dark mode: Black backgrounds, white text (Void/Abyss system)
- Light mode variant: Near-white backgrounds, dark text (for conservative clients)
- Architecture diagrams: Signal blue node systems on dark backgrounds
- Typography: Consistent with brand (Geist/Inter, thin weights)
- No decorative elements — every visual element serves the content
